# 自动研究知识库

围绕用户提出的一个研究问题组织证据，由 Codex 检索、阅读、维护和调用项目知识库。面向用户交付核心知识、方法论，以及对现有研究的具体参考。

## 入口与任务选择

- 本 skill 位于项目根目录下的 .agents/skills/auto-research-knowledge。以 Git 根目录和根 README.md 确认项目位置，路径随仓库移动，不硬编码本机盘符。
- 日常研究讨论进入查库模式：读取当前项目 Research_Knowledge/INDEX.md 和 PROJECT_MAP.md，检索相关笔记，再核对当前任务涉及的研究文件。已在上下文中且仍有效的内容无需重复读取。项目尚无知识库时说明目前为空，查库请求本身不触发初始化或新文献检索。
- 查库模式不自行启动新的文献检索、全文精读或方法运行。需要新证据时说明具体缺口；当前请求明确要求查找、查证新文献、精读、复现或完整研究流程时，执行其中被要求的工作。
- 单独调用 skill 而没有具体问题时，优先沿用当前对话已明确的问题；仍不清楚时只询问问题目标，不自行选择课题并开始大量阅读。
- 阅读新文献时，加载 [文献与证据规范](references/literature.md)；运行复现时，加载 [复现规范](references/reproduction.md)。普通查库不需要加载这两份详细规范。
- 用户当前指令决定本轮范围。仅要求找论文或精读时，将值得复现的方法列为建议；明确要求复现或完整流程时，可自主完成可行的轻量本机复现。

## 首次使用与知识库归属

- 本 skill 随使用者明确选择的项目安装。默认不执行用户级安装，也不把某个项目的知识复制到其他项目。
- 当用户明确要求初始化知识库，或要求开展需归档的新阅读/复现任务而当前项目尚无知识库时，将 [空白索引](assets/knowledge-base/INDEX.md)、同目录的 PROJECT_MAP.md 和 DECISIONS.md 复制到当前项目 Research_Knowledge。仅补充缺失文件，保留已有内容。
- 根据用户当前给出的主题和实际项目文件填写 PROJECT_MAP.md。没有明确的项目工作目录时，先确定目标目录；不要将 skill 的安装目录当成所有项目共用的知识库。
- 只要求初始化时，建立入口、登记主题并结束。新文献检索和复现仍按当前请求启动。
- 日常自动查库的项目规则可参考仓库中的 AGENTS.example.md，由使用者选择合并到目标项目的 AGENTS.md；保留目标项目现有规则。

## 研究上下文

从当前项目的问题地图、README 和用户请求确定研究领域、问题优先级、数据入口及已有结论，不预置某个学校、学科或数据集。

先核对现有研究文件的变量、研究对象、样本层级、处理条件和分析状态，再讨论文献是否可迁移。交接记录提供导航和历史背景；当前结果判断以实际输入、脚本和输出为依据。保留原始变量名、完整数据标识及来源证据。

## 按问题组织工作

1. 将问题写成可回答的目标：要解释的观察、需要比较的机制或方法、期望改变的研究决策。利用已有上下文，只有会改变工作方向的缺失信息才询问。
2. 检索现有知识库和相关研究文件，区分已有依据、仍待核对的记录和证据缺口。知识库为空时如实说明，以当前项目文件建立上下文。
3. 在本轮明确要求的范围内补充文献或计算证据。按相关性、研究设计和证据质量选择文献，不预设固定篇数；同时寻找有区分价值的相反结果或替代解释。
4. 将证据连接到当前问题：哪些机制得到什么支持，哪些条件影响适用性，现有数据能检验哪一环，下一步的成本和预期收获是什么。
5. 完成新阅读、复现或用户要求的更新后，维护相关的单篇笔记、主题、问题记录和 INDEX.md；不要只新增一篇孤立总结。

## 知识记录与修订

知识库只保存于本项目 Research_Knowledge。按任务需要建立文件，不预建空笔记：

- papers/作者_年份_短题名.md：单篇文献，包含 DOI 或稳定来源及原文定位。
- topics/主题.md：跨文献的共同点、分歧及适用条件，链接到单篇证据。
- questions/问题短名.md：问题目标、当前观察、证据综合、对现有研究的建议和未解决项。
- reproductions/任务名/：复现说明与可审查脚本；下载数据、环境、日志和大型输出使用该目录内的本地工作子目录。
- DECISIONS.md：用户确认的协作约定和影响研究方向的决策。记录日期、依据及被替代的决定。

明确区分原论文的实验结果、作者解释、我们的假设、实际计算结果和未执行方案。摘要阅读、全文已核对、补充材料缺失等阅读状态如实标注；跨文献综合继承各来源的证据范围。

同一 DOI 或同一论文的不同版本优先更新既有笔记，记录实际读取版本。新证据改变旧判断时，在相关主题或问题中写明修改内容和原因，链接原有记录。普通查库回答不自动转成已核验的新文献笔记。

## 资源与版本管理

- 可自主运行本机轻量复现。先检查实际环境和小样本耗时；预计长时计算或大量下载时，先给出具体资源估算、可运行方案及较小替代方案，需要扩大本轮范围时再确认。
- 按目标项目既有的 Git 忽略策略保存笔记、脚本和环境描述；采用放行清单的项目需要补充精确路径及必要父目录规则。核对候选文件清单，将下载数据、独立环境、缓存和大型生成物保存在被忽略的 local/ 子目录。未使用 Git 的项目仍可正常保存知识文件。
- 将工作文件保存、Git 提交和 GitHub 推送分别处理，遵循当前任务授权；调用本 skill 本身不要求额外提交、推送或重做登录。

## 完成与汇报

本轮以研究问题为单位收束：形成有出处的证据整理、对现有研究的具体建议，并完成本轮所需的知识库更新。证据不足时交付有依据的阶段判断，列出缺口和仍未完成的工作，保留其状态。

聊天中优先给出核心结论、值得借鉴的方法、与用户研究的关系、下一步行动和知识文件链接；详细技术记录留在知识库。中文解释，保留关键英文术语和原始变量名。复现报告分别说明代码是否运行成功、结果是否达到预先确定的对照标准。
