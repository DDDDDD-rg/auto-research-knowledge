# 计算方法复现

仅在当前请求明确包含复现、运行相关方法或完整研究流程时执行。只要求精读时，可在笔记中提出复现候选。

## 先定义可检查的目标

确定复现哪张图、哪个表或哪项方法行为，记录论文版本、作者代码版本、数据版本、输入条件、比较指标，以及适合该问题的允许差异。原始复现与应用到用户数据是两个目标，分别说明并分别核对。

可做作者代码原样运行、根据方法重写的复现，或小数据演示；根据实际条件选择并准确命名。小数据演示验证方法行为，不直接标成论文结果复现。

## 本机环境与资源评估

先检查实际 Python/R 版本、所需包、可用输入和运行入口，复用现有环境；需要新依赖时使用任务独立环境，避免改变其他分析的依赖。审阅下载脚本的入口和写入位置，再运行。

默认自主执行的是可中止、资源可控的轻量本机任务。无把握时先用小样本、单次拟合或小规模循环测量耗时和内存，再估计全任务；不要通过启动完整计算来判断它是否轻量。

预计长时计算或大量下载时，在启动前给出具体的目标、数据量、下载量、耗时、磁盘/内存需求、估算依据和较小替代方案。超出当前授权范围时，把复现代码、运行命令和估算整理到可审查状态后，再确认扩大范围；继续完成可独立进行的阅读和代码检查。用户已给定预算和范围时按其执行。

## 运行与记录

将复现放在 Research_Knowledge/reproductions/任务名/，以独立目录保存工作。既有研究数据作为输入；本轮未要求改动的正式脚本和结果保持原处。

按需保存：

- reproduction.md：目标、来源、版本、环境说明、资源评估、运行命令、比较标准、实际状态和结论。
- 用于本轮复现的短脚本、参数配置及环境描述。
- local/：下载数据、独立环境、日志、缓存和大型生成输出；默认留在本地。

记录命令、随机种子、输入路径或数据获取方式、软件/包版本、运行是否完成和实际输出位置。需要精确输入身份时记录文件校验值。数据缺失或依赖失败时保留已完成部分，记录具体失败阶段和可行的下一步。

## 核对结果

先核对输入、样本数、预处理和参数，再比较论文目标。根据问题核对数值量级、方向、排序、图形结构或统计量；对随机方法记录随机性和多次运行波动的处理方式。

将“运行成功”和“达到论文对照标准”分别报告。解释差异时先查数据/软件版本、实现细节、随机性和论文未披露步骤，区分实测原因和待验证推测。

在 reproduction.md 中用实际状态说明：仅计划、部分运行、运行完成、对照通过或对照未通过。将验证得到的方法特点和适用条件回写到相关论文及问题记录，更新知识库索引。

按目标项目现有的忽略策略纳入脚本、说明和配置；使用放行清单时逐文件补充规则。local/ 中的数据、环境和大型输出保持忽略，必要时增加相应规则。使用 git status 和候选文件清单核对，避免将复现目录整体放行。
